## 2. 数据设计

### 2.1 schema 增量（向后兼容，旧条目不用改）

```jsonc
{
  "id": "sc_near_face_classroom",
  "zh": "教室午后 · 脸特写",
  "group": "near",            // 新增取值（原 sfw / nsfw）
  "theme": "面部",            // 复用现有字段，特写组用来标部位
  "desc": "……",
  "tags": { "shot_size": "extreme close-up", "dof": "focus on face", "...": "..." },
  "extra": "face, eyes, iris, eyelashes, lips, catchlight",
  "manual_only": true,        // ★ 新增：只允许手动套用，不进随机池
  "level": 0                  // 仍由 build_scenes.py 派生，不手写
```

- `manual_only` 缺省 = `false` → **现有 122 条行为逐字节不变**
- `group` 新增 `near` → `build_scenes.py` 的 `groups` 校验需加一条（`groups` 数组里加一项）
- `level` 由脚本按内容派生（32 条预计全部 L0，个别含 `wet`/`see-through` 的会被抬档，届时如实接受）

## 3. 引擎改动（唯一一处，约 10 行）

### 3.1 `scene_options()` 增加开关

```python
def scene_options(lv: int = 99, include_manual: bool = False) -> list:
    """按档位过滤的场景候选 [(中文名, id, level), ...]。

    include_manual=False（默认）→ 排除 manual_only 预设：
    它们只允许用户显式套用，**不进随机池**（否则会改变现有随机分布）。
    """
    return [(s.get("zh") or s["id"], s["id"], int(s.get("level", 0)))
            for s in scene_list()
            if int(s.get("level", 0)) <= lv
            and (include_manual or not s.get("manual_only"))]
```

### 3.2 `draw()` 内为 n_canon 补"显式套用"通道

```python
pool = eligible_options(key, lv)
if key == "n_canon":
    # manual_only 预设：只有选项权重顶到 3.0（= 面板点「套用」）才进候选
    pool = pool + [(zh, sid, canon_level(sid))
                   for zh, sid, _n in scene_options(99, include_manual=True)
                   if sid not in {en for _z, en, _n2 in pool}
                   and canon_level(sid) <= lv
                   and option_weight(weights, "n_canon", sid) >= WEIGHT_MAX]
```

### 3.3 零影响论证（可执行验证）

- 现有 122 条无 `manual_only` → `scene_options(lv)` 返回值**顺序与内容完全一致**
- `pool` 追加列表在旧数据下**恒为空** → `weighted_pick` 输入不变 → 同 seed 输出逐字节相同
- 验收方式：改造前后各跑 `draw()` 240 次（12 档 × 20 seed），`json.dumps(text+report)` 对比 SHA256 全等

## 9. 决策补充（2026-10-18 已拍板）

**S1 · 腿/脚/手部套用时自动关闭 ③ 五官与表情段 —— 采纳「自动关 + 可恢复」**

- 触发条件：`sc.part ∈ {腿部, 脚部, 手部}`（面部 / 眼与唇 / 上半身与胸 **不触发**）
- 动作：`ui.weights.sections.face = 0`（段 id 为 `face`），并快照原值到 `ui.nearRestore`
- `取消套用` 时恢复快照；页面重载后快照丢失则回落到 1.0，并在状态栏说明
- **不静默**：套用时 `setStatus` 明确写"已同时关闭 ③ 五官与表情段（否则表情/眼神会把画框拉回脸）"，
  卡片上也带 `✂ 关③段` 徽标
- 为什么不会让 F10 变红：`eyes_color` 在 ③ 段，但 `hair_color` 在 ② 段；F10 只要求"发色或瞳色有其一"

**S2 · 「湿衣贴身」保留 L2 原样** —— 与词库判定表一致，该条只在成人及以上档位出现（落在 L2 分组）。
因此 32 条最终分布为：**L0 30 条 · L1 1 条（泪光）· L2 1 条（湿衣）**。

### 已知限制（需你决定是否再动）

**腿 / 脚 组在"自动抽到角色"时常常退化成「半身带腿」**：角色 tag（`xiangling, genshin impact`）
+ 发色/发长锚点会把画框拉回脸，即使 ③ 段已关、即使额外写 `head out of frame` 也压不住
（实测 L11 / N2 两张，加 `head out of frame` 的 A/B 也无效）。

- 根因：F10 要求"有角色就必须绑发色或瞳色"，所以 ② 段不能关；角色又是默认必抽
- 彻底解法（**超出本次批准范围，需你点头**）：腿/脚/手 组套用时**同时清空已选角色 + 关 ② 段**
  （role 为空 → F10 免检，画面才真锁在局部）。这正是当时 S1 的第 3 个选项
- 折中：维持现状，卡片上已写"腿脚特写建议不选角色"；手动清空角色后效果明显更好（对照 T6）


### 补充（2026-10-18 二次实测：清角色并不能救四肢组）

按"自动清角色"落地后重跑：`role=None / hair=None / 自检 16/16`，但 **X_leg / Y_leg / Y_hand / Y_foot
四张仍退化成半身或全身**（`1boy, hetero` 的人数组合、`suspender skirt / tank top / gym uniform`
这类服装标签、`long legs / thick thighs` 身材标签都在把画框往上拉）。

把四肢组 12 条的 `shot_size` 从 `close-up` 提到 `extreme close-up` 也**没有改善** ——
