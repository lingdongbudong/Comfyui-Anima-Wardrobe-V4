## 1. 需求边界

### 1.1 我理解的功能定义

「特写场景搭配」= 在现有「🎬 场景搭配」体系里，新增一类**以局部取景为前提**的固定组合：
一条配方同时锁定 **景别 + 部位焦点 + 机位/景深 + 局部场景与光影**，套用后这些字段不再参与随机。

形态上等价于现有 122 条场景搭配，只是**内容维度从"场景/姿势"转成"取景/部位"**。

### 1.2 明确不做的（除非你要求）

- 不改节点控件个数（避免 `tools/fix_workflows_v12` 那类工作流迁移问题）
- 不改现有 122 条预设的任何字段与档位
- 不改 `weights_json` 的结构与语义
- 不动 `Anima_工作流V3.1.json` 的任何连线
- 不改词库唯一真源 `S:/ComfyUI/提示词/ANIMA提示词生成器.html`（路线 D 除外）

### 1.3 需要你定义的三件事

1. **覆盖哪些部位**（脸 / 胸与上半身 / 腿 / 脚 / 手）
2. **腿脚特写是否允许放弃角色 tag**（这条直接决定效果，且与自检 F10 冲突，见 §4.2）
3. **专用景别是否要进词库**（`lower body` / `feet focus` 目前不存在，见 §4.3）

## 3. 三层可行性

| 层 | 判断 | 依据 |
|---|---|---|
| **数据层** | ✅ 完全可行 | 只需在 `anima_v4_scenes.json` 加条目，`build_scenes.py --check` 自动校验字段名/选项原文/派生档位。写错字段名会在构建期报错，不会静默失效 |
| **链路层** | ✅ 可行（复用 `n_canon`） | `apply_preset()` 不认识来源，`scene_preset()` 已把场景库转成同形状 `{字段:值}` + `n_extra`。新预设自动获得：档位闸门、权重让路、锁定让路、不可裁剪保护 |
| **UI 层** | ✅ 可行（两档做法） | 做法一：在现有「🎬 场景搭配」页加"特写"筛选开关（≈30 行）；做法二：新增第 4 个页签「🔍 特写搭配」（≈120 行，需在 `:453` 的 tab 表里加一项） |

## 4. 三个必须解决的硬问题

### 4.1 随机池污染（会让"现有行为"发生变化）

**问题**：`n_canon` 的默认字段权重是 `1.0`，且候选池包含全部场景预设。也就是说
**现在不做任何操作，随机抽取也会命中场景预设**（实测 `draw(level='sfw', seed=9)` 直接套了 `sc_balcony_night`）。
新增 N 条特写预设进同一池子，会让"随机命中预设"时的内容分布偏向特写 —— 这就是对现有行为的改变。

**方案**：特写预设打 `"manual_only": true`，候选池组装时过滤：
只有该选项**权重 ≥ 3.0**（即用户显式套用）才进入抽取，否则一律不进随机。
- 现有 122 条无此标记 → 随机路径**逐字节不变**（可用固定种子对拍证明）
- 面板套用天然给 3.0，所以"点一下就生效"
- 实现位置：`rules.eligible_options('n_canon', lv)` 或 `draw` 内池子组装一处 + `scene_preset` 透传标记

**代价**：需要改 `anima_v4_rules.py`（约 10 行）。这是**唯一一处**碰引擎的地方。

**替代（零引擎）**：接受污染 —— 随机输出里会开始出现特写配方。不推荐。

### 4.2 腿脚特写的"脸锚点"压制（效果与自检冲突）

**实测证据**（2026-10-18，本机 8188，9 张对照图）：写 `pov legs, from above, legs, feet`
但同时带 `black long hair, blue eyes` + 情绪词时，**画面被拉回上半身**，腿只剩底边一条；
砍掉脸/发色锚点、只列 `thighs, knees, calves, ankles, feet` 后双腿双脚才完整入画。

**冲突**：压制发色/瞳色会触发自检 **F10 红**（有 role 就必须绑发色瞳色）。
唯一干净解法是**腿脚配方不写 role**（`role` 为空 → F10 免检），也就是"腿脚特写不出角色 tag"。

**方案对比**：

| 做法 | 效果 | 代价 |
|---|---|---|
| 只靠"配方里写 shot_size + 部位 extra" | 面部 ✅ / 腿脚 ⚠️（脸锚点残留） | 零引擎改动 |
| 配方带 `drop: [emotion, eye_gaze, mouth, role]`，套用时清空这些字段 | 面部 ✅✅ / 腿脚 ✅ | 需改 `apply_preset()`（约 15 行）+ 明确"drop 只在套用处生效、不写进 weights" |
| 面板上给"腿脚特写是否保留角色"开关 | 最灵活 | 多一个入口，与你"同一个设置只留一个入口"的口径有摩擦 |

### 4.3 专用景别要不要进词库

`lower body` / `feet focus` 不在 `shot_size` 候选里。两条路：

| 做法 | 说明 | 影响面 |
|---|---|---|
| **走 `extra` 自由标签**（推荐） | 配方把 `lower body, legs focus, feet` 写进 `extra` 字段，逐标签过档位闸门 | 零词库改动。实测这些标签档位全是 **L0**（`pov legs` 是 L1），不会把整条顶到高档 |
| 进词库真源 | 改 `ANIMA提示词生成器.html` → 重跑 `export_v3_pools.mjs` → 重算 `levels.json` → 零漂移对拍 | 影响 `check_v3_pools.py`、`levels` 派生、面板候选；工作量大且动真源 |

**注意**：`extra` 里的标签**不在权重面板里出现**，用户不能单独关，只能整条关。这是已知取舍。

## 5. 影响面矩阵

| 改动点 | 受影响模块 | 风险 | 回滚 |
|---|---|---|---|
| 新增预设数据（JSON） | 场景库、`/scenes` 载荷、`/pools` 的 `n_canon` 候选、权重袋 | 低（数据） | 删条目 + 重跑 build |
| `manual_only` 过滤 | `eligible_options` / `draw` 池子 | **中**（热路径） | 保留开关，默认关闭 |
| `drop` 压制 | `apply_preset` + 自检报告 | **中**（会影响 F2/F10 口径说明） | 无 `drop` 的预设行为不变 |
| 面板新页签 | `js/*.js`、`av3_ui_smoke.mjs` 夹具 | 低 | 删页签 |
| 词库新增景别 | HTML 真源、导出、levels、零漂移对拍 | **高** | 不建议本轮做 |

**不会受影响**（已核对）：
- 现有 122 条预设的 id / 字段 / 档位 / 套用结果
- 节点控件个数与顺序（`weights_json` 结构不变，只多几个值为 0 的 option key）
- 五级档位闸门、三层权重、锁定字段、裁剪保护
- `Anima_工作流V3.1.json` 的连线

## 7. 附录：实测数据（本机引擎实跑，非推测）

**候选特写标签的档位判定**（`R.tag_level`）：

| 标签 | 档位 |
|---|---|
| face / eyes / iris / eyelashes / eyebrows / lips / nose / blush / skin / sweat | L0 |
| close-up / extreme close-up / portrait / upper body / lower body | L0 |
| legs / bare legs / thighs / knees / calves / ankles / feet / bare feet / toes / soles | L0 |
| depth of field / blurry background / focus on face / catchlight / detailed eyes | L0 |
| head out of frame / cropped legs / leg focus / feet focus / face focus | L0 |
| **pov legs** | **L1** |

→ 结论：部位词全部可安全写进 `extra`，不会把 SFW 配方顶到高档位。
⚠️ 但引擎对**未知标签默认判 L0**，写错也不会报错，需人工把关。
